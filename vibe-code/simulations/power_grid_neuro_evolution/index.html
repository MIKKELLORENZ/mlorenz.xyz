How all of this works — the long version

Why a power grid is hard to run

Electricity is not stored in the wires. Whatever the country is using right this second is being made right this second, somewhere, and travelling to you down metal cables. Nobody chooses which cable it takes — physics does, and it splits the flow across every possible route according to how easy each one is.

That is the trap. You cannot steer electricity directly. If a line is carrying too much, you cannot just tell the electricity to go somewhere else. You have to change something else about the system until the physics decides differently.

And you have to, because a line carrying more than it was built for gets hot, sags, and eventually a protective switch cuts it out to save it. The instant that happens, every amp that was using it reappears on the neighbouring lines. If they were already busy, they overload too, and cut out, and so on. A grid can unravel in minutes. Real ones have: the north-east of America in 2003, most of Italy the same year, half of Europe wobbling in 2006.

The two levers

Turn power stations up and down. If a line running south is too full, make less power in the north and more in the south, and less has to travel. Real, reliable — and expensive, because the cheap station was already running and the one you are turning up is dearer. That is why it is a lever and not a free lunch.

Rewire. Switch a line out on purpose, or split a substation so that what was one junction becomes two. The flow re-routes. Free — and genuinely dangerous, because you have just removed a road from the map and the traffic has to go somewhere. Real operators do it, carefully, one move at a time, checking each one first. So does this simulation: one switching move per five minutes, maximum.

What the AI actually is

6 756 numbers. That is the whole operator. Feed in what is happening on the grid, multiply and add through those numbers, and out comes a decision. There is no code in there saying “if a line is over 100%, do X” — just arithmetic that happens to produce sensible behaviour once the numbers are right.

Getting them right is the trick, and it is not done by teaching. It is done by breeding. Make a few dozen operators with random numbers. Give them all the same day to run. Score them. Throw away the worst, keep the best, make children by mixing two parents and nudging some numbers at random, and run the whole thing again tomorrow. Repeat a few hundred times. Nothing is ever explained to them; the ones that happen to be less bad simply have more descendants. This is a genetic algorithm, and it is the same idea as actual evolution, run at a few generations per minute.

The clever bit: one brain, any grid

An obvious design would give the AI one input per power line. But then a brain grown on a fourteen-substation grid is meaningless on a thirty-substation one, and everything it learned about line 7 tells it nothing about line 8. It would be memorising, not understanding.

So instead the same small set of numbers is applied to every line, and again to every substation, and each one passes a short message to its neighbours — twice, so news travels two junctions before anyone decides anything. It is the same idea as how you recognise a face in any photo without needing separate eye-detectors for every position.

The payoff: a brain bred on the 14-substation grid runs, unchanged, on a 30-substation grid it has never seen. That is the only honest way to ask whether it learned electricity or just learned this grid.

What it can see

For each substation: voltage, how much power is being used and made there, how much spare capacity the local stations have. For each line: how full it is, how hot it has got, whether losing it would cut part of the grid off entirely. Overall: the time, the spare capacity in the whole system, a weather forecast half an hour ahead, and how bad things would get if any single line failed right now.

Plus two numbers a real control room has on a screen: for the most stressed line, how much would turning each power station up help?, and what would switching each line off do? The ordinary programs it races against read exactly the same two numbers. The AI gets no secret information.

The weather is invented, not recorded

No real data is used anywhere. The sunshine is worked out from actual orbital geometry — where the Earth is in its year, how high the sun sits, how much atmosphere the light has to cross — and then multiplied by a randomly generated cloudiness that drifts over about an hour, so clouds pass instead of flickering. The wind is random but with the statistics real wind has, fed through a real turbine’s power curve: nothing below a light breeze, full output in a good blow, and a hard cut-off in a gale, because turbines shut down to protect themselves — the whole farm at once. Demand is a daily rhythm (low at 4am, peak in the evening) times a weekly one, plus random drift and the occasional sudden jump.

Everything comes from one seed number, which means the same day can be replayed exactly. That is what makes the race fair: every operator faces the identical weather and the identical faults at the identical minute.

How the physics is calculated

Every five simulated minutes the program solves the real equations for how power flows through a network — the same maths, in the same form, that actual grid engineers use. It is a system of non-linear equations with no direct solution, so it is solved by repeated guessing and correcting until it settles, several times per step. There is a fast approximate method for testing “what if this line failed?” across every line, every step, and a slow exact one for what actually happens. Getting a whole day of this to run in under a second in a browser is most of the work in the code.

How the score works

Everything is money, which is how the real industry thinks. Electricity delivered earns €70 per unit. Fuel costs whatever that station costs to run. Changing a station’s plan at short notice costs a premium on top. Flipping a switch costs a small fixed amount, because a real switching operation needs a person to authorise it and carries risk. Paying a wind farm to stop costs money. And electricity you fail to deliver — the lights actually going out — costs €3 000 per unit, roughly forty times what it would have earned.

That last number is the whole design. It means the cheapest way to run the grid is also the way that keeps the lights on, so a program chasing money is automatically chasing reliability, without anybody having to write down a safety rule.

The one thing deliberately left out

Every real grid operator lives by a rule called N-1: at every moment, the grid must be able to survive losing any one line, immediately, without anything else breaking. It is the single most optimised number in the industry.

Here it is measured every five minutes, drawn on the chart — and never paid for. Not once. The question being asked is: if you pay an operator only to deliver electricity cheaply and not break things, does it discover safety on its own? If the reward already contained the safety rule, the question would be meaningless. There is a switch to turn the payment on, and it is off by default for exactly that reason.

The answer this run gives is a fairly clean no. It ends up about as N-1 secure as doing nothing at all. It learned to survive the trouble that actually happens; it never learned to stand ready for trouble that merely might.

The mistake that nearly sank the whole thing

For a long time the AI learned nothing, and the reason turned out to be almost funny. A well-built power grid is boring nearly every day. Nothing goes wrong, so doing nothing is exactly the right answer, so every operator in the crowd scores the same to the penny and evolution has nothing to choose between them. Worse than useless: on a boring day the only operators that differ from the crowd are the ones that did something, and doing something costs money — so a boring day actively breeds out the instinct to act at all.

The fix is to audition the day. Before spending a whole crowd on it, the program cheaply tries out nine possible days and keeps the ones where sitting on your hands demonstrably costs you. One slot is always given to the quietest day it found, though, because an operator that has only ever seen crises learns that fiddling always pays, and then fidgets expensively through every calm Tuesday for the rest of its life. It has to learn both halves of the job.

What this is not

A snapshot every five minutes, not a film: nothing here happens in fractions of a second, which is where a lot of real grid drama lives. No transformer tap changing, no HVDC links. And the operator is never allowed to switch customers off on purpose — when the lights go out here it is because the automatic protection did it, after everything else had already failed.
